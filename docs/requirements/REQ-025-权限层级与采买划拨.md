# REQ-025｜最高权限、退款净额与财务本人采买

来源：2026-09-19用户对D34三个子问题的答复。当前规则见[PRODUCT](../../PRODUCT.md)，执行见[PROJECT_LOG](../../PROJECT_LOG.md)。本轮只同步需求，未实施真实数据或权限修改。

## 用户原文

> 第一个问题按你说的来，第二个问题首先最最高的权限来自于开发者我，可以直接访问源码，从源码修改数据，第二管理员权限，可以调整团队所有成员的身份、费率、以及可以调阅修改团队的所有数据，第三就到财务、校长等职务，开发者可以设定谁具有管理员身份，当然开发者也可以看到所有数据，
> 第三个问题，财务老师采买产生的费用也从个人账户发起至财务账户，直接通过无需审批，直接划转欢乐豆，但是不论是谁的财务审批都必须附上对应的单据，申请截图待查

## 被接受的第一项建议

用户“按你说的来”对应上一轮建议：已退款费用退出后续净课时费统计；退款审批当次只冲原笔，下一次正常新增/更正时使用扣除退款后的净额，并沿现有整月重算处理未退款费用。

例：当月原接收20000、推荐0，退款10000当次只冲所选费用；后续新增1000，正常计算取净额11000而非21000。已退款笔不能被后续重算恢复；作为推荐输出的退款也应从该老师的推荐扣减项剔除。

## 权限层级

1. 用户本人作为开发者是最高维护主体，可访问源码、查看修改所有数据，设置或撤销管理员。该权力不依赖普通管理员授予；不将任何开发人员或AI工具默认等同用户本人。
2. 管理员可调整团队全员身份、费率并调阅修改全部业务数据，包括财务、工资、学生、费用和历史；下级职务和范围由管理员配置，但管理员身份授予仍只由开发者决定。管理员不因业务身份获得源码控制权。
3. 财务、校长等职务按已获授的业务和组织范围操作。开发者/管理员可查全部财务单据及截图；其他管理职务不能因名称中有“管理”而自动获得全量财务或工资。
4. 全部业务可更正与历史可追溯同时成立：保留前后值、原因与记录；账务更正通过关联差额/冲回，不无痕抹旧账。普通成员不改昵称，管理员/开发者可更正展示昵称并保留历史，稳定人员/账户ID不变，不凭名字改动迁移资金。此为管理员可改身份数据的实施衔接。
5. 源码与数据库是不同对象；开发者可通过有权限的代码/维护工具访问修改实际数据。文档说明最高控制权，不声称此次已经执行源码/数据改动，也不限制开发者必须由管理员授权。

## 财务本人采买与凭证

- 财务老师从个人页面向财务业务账户发起本人采买申请，资料齐全后自动通过且直接划转欢乐豆，无须再切财务页手工自审或第二次执行；自动规则、申请人与实际账户记录清楚。
- 申请身份与资金方向分开；两账户实际扣加方向已提问，等待补答，不能把“申请到财务”擅自解释成个人扣款。
- 所有人的财务申请均须对应单据和申请截图留查，自动通过同样适用；材料须上传完整、可读取。草稿可存，缺件不能提交成功、审批通过或先划转后补材料。
- 申请截图与后续付款回执不是同一对象；不要求未付款时提供未来支付完成回执。原件、引用、版本、操作及处理记录永久保留并进入完整备份。
- 本人采买例外不扩张为所有报销/普通对外付款/退款/人工调账免审；普通业务仍按既有流程；财务本人其他报销仍保留已确认的手工自审能力，人工调账仍不得自审。资金方向确认后同步金额例与退款撤销原来源规则。
