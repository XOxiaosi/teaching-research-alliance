# REQ-017｜现金工资、校区与个人分离、可配置初始比例

来源：2026-09-17当前任务中的用户文字答复。仅保存文字来源与覆盖关系，不声称核验现金付款或真实财务数据。产品要求统一维护在[PRODUCT](../../PRODUCT.md)，执行证据见[PROJECT_LOG](../../PROJECT_LOG.md)。

## 最新原文

> 工资是以现金发放给老师，在欢乐豆的记录中记作扣除欢乐豆多少金额，与这些分配完全无关，校区作为职务只需要记录校区的收入，校长作为老师的收入进行相应分配之后单独记录老师个人页面中，两者完全无关，每项设定初始默认值，要求全部都能由管理员进行修改

## 本轮前序上下文

用户此前要求以个人教师账号为基础区分个人与职务，职务可以更换、兼任，个人可查看任职、对应分配、职务看板与团队人员。当时关于职务“工资”的表述，本次明确应拆成课时分润与现金工资两类，不能继续将两者混用。前序提出的职务负责人调整可调部分仍保留。本次只明确管理员可改全部参数，不能由此推断撤销负责人可调需求；具体项目、额度和范围登记D28，细则明确前沿用仅管理员修改的执行边界。

## 已确定的覆盖关系

1. 工资在线下以现金发给老师，系统记录老师个人扣豆，与课时费分配、档位和职务分润无关。覆盖REQ-016的工资发起人扣豆/老师加豆内部转账方向；不因此改变奖金和报销内部划拨规则。
2. 校区职务收入只记校区独立账务主体及校区看板，校长作为老师得到的个人分配记个人页，不能把校区2%自动记为校长个人收入。没有新增一项独立“校长个人抽成”或从校区拨给校长的规则。
3. 每项分配参数有初始默认值且全部可由管理员修改。六项初值6%、7%、5%、2%、2%、1%，一对一9%、小班12%、原档位及上限16%均保留为可配置初值；Q原文无默认数值，启用前由管理员配置，列D27，不擅定0%或把算例1.5%当默认。
4. 管理权限与收款身份分开，任职不自动赋予比例编辑权，负责人可调细则见D28；职务更换保留历史个人收入，校区账务主体不随人转移。

## 实现解释与沿用规则

以下是为使明确要求可验证而采用的执行解释，不是额外用户原话：

- 沿用财务确认现金已发后扣豆、计划不扣的流程；保留每月1日北京时间00:00工资待办。确认幂等；补发现金只扣对应差额；账务错误保留原记录并关联冲回，不宣称现金已退。现金工资扣豆不再自动生成财务/校区账户欢乐豆支出，不通过提现或付款单重复扣同一笔工资。
- 默认配置与老师个别配置分层：个别配置优先；默认六项变更只影响使用该默认的本财年适用流水，不覆盖个别配置。沿用表8政策修改重算本财年的规则。
- Q默认作为逐笔创建的带入值，每笔保存实际值和配置来源；修改默认不覆盖已经保存的逐笔Q，明确改单笔Q才重算该笔涉及月份。此解释用于保留逐笔配置语义。
- 授课老师仍为100%减其他项目后的剩余份额，管理员通过调整参数改变其比例；不额外设置与守恒计算冲突的第十项份额。工资金额是独立月度计划，不属于课时费比例。
- 校区与校长个人分开已明确，其余财务/管理员业务钱包范围保留D24；提现D25和医社保公积金D26不由本次工资方向外推。

## 验收示例

- 个人余额6000豆，工资计划4900不扣；现金已发4900并确认后余额1100，校区收入和原课时分润明细不变；计划改5300不扣，补发现金400并确认后余额700。重复确认仍为700。
- 某校区收入200豆，校长个人业务分配6600豆：校区页200、个人收入页6600，不能合并为个人6800；个人发现金工资4900并确认后个人余额1700（假定无其他变动），校区收入仍为200。
- 无老师个别配置时使用当前默认六项；有个别配置时优先个别值。所有比例仅管理员可修改；Q未配置且逐笔缺值时不能默认为0并提交。
