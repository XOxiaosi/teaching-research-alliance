# REQ-018｜总部财务界面与分区管理职责

来源：2026-09-17当前任务中的用户文字及异步问题答复。当前要求见[PRODUCT](../../PRODUCT.md)，执行证据见[PROJECT_LOG](../../product-log/PROJECT_LOG.md)。本文件记录演进，不让本轮前一个表述覆盖用户后续修正。

## 第一条用户原文

> 现金工资这个事情不需要体现在个人老师页面，在财务界面设定好哪些老师需要发放工资，需要扣除多少欢乐豆
> 有一个分区财务，作为一个展示看板而不是真正的财务工作职能，展示看板需要展示这个分区名下的各校区收入以及分区总收入，所以这里面的逻辑是总部（管理员+财务）-分区-校区

## 后续问题与用户修正（优先）

Agent询问原分配表中的分区财务1%是否继续保留为独立分润，并说明拟将分区总收入按下属各校区收入之和展示，避免重复记账。

用户答复：

> 分区也有自己的收入那分区不适合单独作为看板，分区财务与其他页面交互逻辑相同，作为一个职责，也可以管理底下所有校区的人员安排与人员名单，并且可以看到校区的营收以及总分区营收

## 已明确的产品规则

1. 工资名单、计划及扣豆金额在总部财务界面设置，管理员按已有管理权限访问。老师个人页面不展示现金工资模块、计划、金额或工资扣豆明细；余额依旧包含真实扣减。覆盖REQ-017中的“个人页面单列工资扣豆”，不改现金已发确认扣豆、计划不扣及幂等记账方向。
2. 组织结构是总部（管理员和真正办理财务的人员）—分区—校区。分区财务是一项可任命、兼任及切换进入的管理职责，有自己的收入，也可查看和管理本区下属校区人员名单及安排，不再限制为单独只读看板。
3. 分区职责可以查看自身收入、各校区营收、分区总营收；仍不自动拥有总部的工资、付款、报销审批或调账能力。基础个人业务和其他已授权职责按各自视角执行。
4. 在原1%去留问题下用户明确分区有自身收入，保留已有分区分润项目及原1%管理员可改初值，不擅自取消或改变其他分润份额。临时D29已解决，不留待决定项。

## 执行解释与既有边界

- 沿用已向用户说明的聚合口径：分区总营收按同期间各校区收入合计，校区收入沿用“所属校区”分配收入；分区自身分润另列，不把组织汇总再次记成分区或负责人收入。没有将营收改成全体教师课时费原额，也没有把自身分润与校区合计再次相加。
- 区内人员安排先落实为本区各校区人员名单、必要资料及老师所属校区调配，记录生效时间和审计；不能外推为跨区调人、编辑个人敏感资料、创建/停用登录账号、任意授予系统权限或修改比例。未明确的负责人可调比例仍归D28。
- 每校区在同一生效时点属于一个分区；调配和组织变更保留历史归属，不能把旧期分润自动搬到新校区/分区。
- 总部财务配置哪些老师应发工资，仅对生效名单生成待办；设置计划不自动扣豆，现金已发后确认扣减仍沿用REQ-017。现金实付元与扣豆按原1:1对应，没有新增两项金额可任意脱钩的规则。
- 个人视角不返回工资字段；同人兼任总部财务须切换才能查看。管理员完整备份和总部财务审计仍保留全部工资、扣豆及更正，不因个人不展示而删记录。

## 验收示例

- 财务为A老师设置工资及扣豆4900，计划保存不改余额；确认已发后，原6000豆余额变1100。个人页显示1100但无工资项目或明细；总部财务页保存名单、计划、现金确认和扣豆，分区职责无权读取。
- 某分区自身分润250、校区A收入200、校区B收入300，职责页分别显示自身250、校区200/300、分区总营收500；聚合不增加账户余额，不能将其作为负责人个人750。
- 同区校区A老师可按生效时间安排到B，旧期收入仍按旧归属；跨区调配及工资/调账接口被拒。岗位人员更换保留历史数据，不复制登录账号或重复收入。
