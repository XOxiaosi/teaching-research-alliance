# 推荐创建与首次接收的实现边界

产品真源：[PRODUCT F03](../../PRODUCT.md#f03生源推荐接收与期间课时费表2)。本文件是技术设计，是否实现以执行日志和代码验证为准。

## 推荐创建

- `POST /v1/referrals` 输入接收老师、学生显示名、课程、班型、幂等键；输出方由已认证人员确定，客户端不得提交收入身份、校区或导师。
- 服务端按管理员维护的业务身份和有效规划导师职责解析并保存创建时身份版本。规划导师直接介绍使用规划类基础池且不向上递归分导师；规划师的导师份额仍按费用所属周的有效管理关系计算。
- 创建学生独立记录、待接收推荐、21天截止、提交事件与幂等记录在同一事务。不同请求即使同名同课程也不合并；同键同参数重放，参数不同拒绝。
- 接收对象必须为正常授课教师，输出方校区和身份关系保存可追溯快照。收费账户初始采用接收方；后续代收功能单独实现，不产生线上支付。
- 新模型须区分旧数据缺失快照与新记录，不能给旧记录虚构身份历史。结算对新记录使用固定的介绍身份，避免其后撤职或切页面改动已建立推荐的价格家族。

## 首次接收

- 仅接收本人，带预期版本和幂等键，明确选择正常场地或本人有效默认场地。
- 原子保存接受事件、所选场地及所有者/自用快照；不授予场地共享查看或提现权限。
- 待接收记录可能已有费用。首次接收不能暗中移动已有费用的场地分润；涉及冲突时返回需要独立场地变更的明确错误，不把过去周最近场地自动解释为当前默认。
- 普通周场地变更另做带生效周的重算命令；暑期或其他需管理员处理的范围不在接收命令中绕过。

## 验证重点

同名独立、并发幂等、身份切换不改介绍来源、导师直接介绍无递归、接收对象越权、缺失/停用场地、期限与版本冲突均不留下部分写入。接收已有费用时账本与历史快照保持一致；后续场地修改由单独重算测试验证。
