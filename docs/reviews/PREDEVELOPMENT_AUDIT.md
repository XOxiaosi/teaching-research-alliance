## 条件计算样例

以下16%封顶算例使用默认上限；D07现已确认管理员可以修改，实际计算须使用对应生效版本的上限。

下列样例只验证：**在人工指定应采用哪一条抬升档后**，分配公式和 16% 封顶的代数结果可复算。原区间表按字面存在重叠，不能据此把任何一个净课时费唯一映射到某档；样例不解决区间、期间或舍入政策。

### 样例 A：假定已确定采用 `+0.5%` 档的默认分配

设 `F=10,000`，一对一，接收方当月净课时费为 `8,000`，`Q=1.5%`，且表8没有个性配置。

- **前提：** 业务决定本笔采用 `6,000 < x <= 8,000` 的 `+0.5%` 档。则一对一基础 9%，`R_final=9.5%`。按原表字面，“-30000 及以上”也会覆盖 `8,000`，所以这不是原表的唯一选档结果。
- 默认六项比例合计 `6%+7%+5%+2%+2%+1%=23%`。
- 转介绍 950，咨询平台 150，教研组长 600，指导导师 700，场地运营 500，所属校区 200，平台财务 200，分区财务 100，授课老师剩余 6,600。
- 九项金额合计 10,000，代数守恒。

### 样例 B：假定已确定采用 `+4.5%` 档时的封顶

设小班课且净课时费为 `16,000`。**前提：** 业务决定采用 `15,000 < x <= 16,000` 的 `+4.5%` 档。则 `min(12%+4.5%, 16%)=16%`。按原表字面，首档同样覆盖 `16,000`，故本例只证明封顶算式，不能证明原表可唯一选出 `+4.5%`；也不代表 `16,000` 以上已有可用口径。

### 算术证据的独立复算

已用 Decimal 对上述条件算例和反例复算，证据为 [calculation-examples.json](/Users/xiaosi/Developer/artifacts/teaching-research-alliance/PRE-001/calculation-examples.json)：条件样例 A 的授课老师剩余为 `6,600`，条件样例 B 的封顶为 `16%`，小额独立四舍五入为 `0.04 > 0.03`，90% 六项比例加 16% 和 1% 时授课剩余为 `-70`，合成的表7余额代数样例为 `570`。该文件明确为文档算术验证，并不证明业务区间、期间或入账口径已解决，也不代表业务代码已运行通过。
