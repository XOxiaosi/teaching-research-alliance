# 学生周费用退款

本设计落实 [PRODUCT F06/F08](../PRODUCT.md#f06单笔课时费分配与收款记录)。实现及验收状态统一见[开发日志](../product-log/PROJECT_LOG.md)，本文不表示退款功能已完成。

## 申请与批准

授课老师从自己的单一学生/课程推荐记录中选择一笔或多笔周费用，填写原因并上传业务单据及申请截图。申请冻结明确费用ID集合、提交时版本与金额，用于核对原请求；申请或驳回都不冲账。不得静默扩大为该学生全部历史、混入另一老师/课程、接受单笔部分金额退款。

总部财务批准时，以所选每笔费用当时最新有效分配及入账链为准，整笔冲回到原收款账户。原申请、原费用、历史版本与附件都保留，费用显示已退款；系统处理不代表线下现金已经退给家长。

状态为 DRAFT → PENDING_APPROVAL → REFUNDED 或 REJECTED。批准与所有冲账在同一事务完成；任一笔已退款、失效或缺少可信有效分配，整单拒绝，不跳过冲突项后把单据标成成功。零金额费用可记录退款结果，但没有非零分录时不虚造资金事件。

## 数据职责

- 申请快照保存申请人、单一推荐记录、原因、提交时身份与明确费用集合，以及当时版本/金额/周/月；它不替代批准时有效分配。
- 附件绑定保存提交时选择的具体READY版本，成功提交后封口。批准核验原件；驳回允许处理无法读取的坏原件，但不能把损坏的申请事实当作正常数据。
- 决策保存总部财务GLOBAL身份、理由、批准/驳回时间及单据版本。
- 每个周费用至多一条生效退款记录，关联申请、批准时实际使用的分配快照、原金额和反向依据。唯一约束与费用行锁共同防止重叠申请重复冲回。
- 原周费用、原分配快照及账本均不覆盖。生效退款记录用于查询和后续计算排除，不通过把原课时费改成负数或零表示退款。

## 账务与锁顺序

批准校验最新快照的费用版本、各项非负分润、总额守恒、收款账户映射及有效入账链，然后将各项实际净额取反。多笔按账户/类别合并为一个退款事件，不按当前费率或当前任职重新分配。余额允许变负，已发生提现保持；原收款账户停用也不把冲回转移到新账户。

正常月份结算的一次入账可能合并多笔费用，因此历史核对以完整计算批次为单位：读取该批次每笔费用的新旧快照，合并账户/类别差额，再与原账本逐项核对。不能把批次汇总分录假定为某一笔费用的独立分录。当前费用版本尚未完成结算、原账户对应关系缺失或历史链不一致时，批准失败并保持整单不变。

所有操作遵守：命令锁与原键重放检查 → 退款单据锁 → 所涉月份按顺序取得结算锁 → 所选费用按顺序取得行锁 → 统一锁定全部账本账户与余额 → 冲回及单据结果一并提交。与正常周费用的月份、费用、账本锁序保持一致，避免批准与更正交叉覆盖。

## 后续结算与展示

退款批准当次只冲所选费用，不立即重算其他费用。后续正常新增/改错触发月份结算时，接收收入和推荐扣减均排除已退款费用；受影响教师使用更新后的净课时费取档，其他有效费用可能产生差额。已退款费用不得再编辑、参与分配或被重算恢复。

个人收入读取排除退款费用原有效快照；周费用页面仍展示原金额及退款标记。余额使用真实原账本加唯一反向，不按页面状态再扣一次。原申请人只按个人当前财年查看，获授权总部财务与管理员/开发者保留管理历史；普通职务不会因此取得退款办理权。

同一费用允许在批准前出现在不同申请中。一份批准后，其他待审申请仍可读取原申请及费用的已退款状态，财务可以驳回；不得把别单的退款生效记录当作本单已冲账。批准其他重叠申请必须整单提示冲突。

## 必需验证

覆盖申请后更正再批准、同周换组长后冲回新有效收款人、多笔中一项冲突导致全单无变化、两申请重叠并发、批准与周费用更正两种先后顺序、零金额无分录、负余额、坏原件批准失败而驳回成功、原键跨年恢复，以及退款后下一次正常月结算同时排除推荐和接收两侧且不恢复已退款收入。未通过这些场景不能将退款标为可交付。
