# 财务附件实现契约

产品语义以 [PRODUCT F08](../PRODUCT.md) 为准，执行进度只见 [PROJECT_LOG](../product-log/PROJECT_LOG.md)。本文描述 DEV-008 技术分层，不表示接口已上线或财务流程已验收。

## 原件存储

- 初期使用服务器本地私有目录，由显式配置指定源码目录之外的位置。生产不得复用测试临时目录；根目录及其父目录必须受信任，不能被非受信任本机用户替换。所有应用文件访问仍须通过单据授权，文件目录不由静态网站暴露。
- 根目录与子目录权限0700、原件0600，目录属运行用户。服务端UUID决定对象名，原文件名只作显示；拒绝路径分隔符和控制字符。
- 每文件上限20 MiB，可配置更小值。流式累计字节并检查声明大小和SHA-256；PDF/PNG/JPEG魔数用于识别媒体类型。字节存储原语不负责完整格式解码，不能把魔数匹配宣称为文档可正常渲染。业务READY前的可读取验证由附件业务层负责。
- 完成流式写入和文件同步后，以同文件系统hard link原子发布，不使用会覆盖目标的rename。已有版本拒绝覆盖；新版本使用新UUID。
- 读取先校验常规文件、字节数、哈希及媒体类型，再交给下载/备份调用方；拒绝符号链接和非普通文件，限制分配内存。下载应由授权层设置attachment和nosniff，不返回存储路径。

## 跨文件与数据库的一致性

- 财务单据和附件版本预留在数据库；附件版本经历UPLOADING→READY或FAILED，已终结的版本不可覆盖或删除。
- 原件先发布，数据库后记录READY。数据库失败不能立即删除已发布对象；业务层按预留versionId和哈希对账，避免READY先出现却没有文件。
- 发布后同步或清理异常以`AttachmentPublicationError`区分：包含已写入原件元数据、目录是否完成同步、是否需清理及临时对象标识。调用方应保存恢复待办，不当成“完全未写入”而覆盖该版本。
- 未发布时清理失败通过`AttachmentCleanupError`保留随机临时对象标识及原错误原因。标识供内部审计和后续受控恢复任务使用，不通过普通API错误输出。恢复只清理已确认失败且无READY绑定的临时对象，不批量删除历史原件。
- 原语异常不等于账务变化。存储模块不调用账本，不自行批准或提交单据。

## 单据与版本绑定

- 草稿归属于登录本人，附件逻辑槽归属于具体单据，原件版本有唯一编号、上传人、时间、用途、哈希和字节数。
- 提交/审批/自动通过之前必须有完整可读取的对应单据和申请截图；所用具体版本在业务事务中固定绑定。后续付款回执作为完成阶段的新绑定，不能替换提交时证据。
- 同一附件修改须产生新版本；旧版本和绑定永久留存。审批/入账服务在事务中验证附件归属、用途、READY及读取完整性，不能只相信客户端附件编号。
- 完整导出复用 [备份规范](EXCEL_BACKUP_SPEC.md)：清单与原件逐项对应，READY原件缺失或哈希不符则整次备份失败，不能放空文件冒充成功。

## 授权边界

- 草稿申请人仅维护本人草稿证据；已提交内容及原绑定不原地改写。
- 总部财务、管理员、开发者及其他获授权查阅者按单据类型与范围读取。分区、校长、组长、导师及场地共享看板权限不自动包含财务凭证或银行卡。
- 上传、下载和单据提交每次重验当前会话与权限。附件服务不自行扩大资金账户操作权，也不提供匿名文件链接。

## 集成验收

除字节存储测试外，业务接入必须验证：上传预留/READY/失败恢复、原件可读取验证、版本和绑定不可变、单据权限及撤权、缺证据拒绝提交、财务自动划拨不能绕过证据、下载不泄露路径、完整备份含历史版本。基础原语测试不代替这些业务门禁。
