# DEV-008｜学生退款后端与共享客户端

业务依据：[PRODUCT F06/F08](../../../PRODUCT.md)；设计：[REFUND_DESIGN](../../../docs/REFUND_DESIGN.md)。当前进度和最终门禁统一由[开发日志](../../PROJECT_LOG.md)记录。

## 可核验行为

- 老师冻结同一学生/课程的一笔或多笔原周费用和具体凭证版本；提交及驳回不改变余额。
- 总部财务批准后，按各原笔最新有效分配一次性冲回；不按今天的岗位和费率重新分配，也不在批准当次重算其他费用。
- 申请后费用更正、已发生分配修正的组长变化、零金额、停用账户及负余额均有隔离数据库场景。组长场景提供已生效关系作为输入，不代表管理员关系变更界面已经完成。
- 同键重试、两份重叠申请、跨月集合、费用更正与退款并发、末端写入失败均验证单次入账或完整回滚。
- 原记录保留金额与版本并标已退款；以后正常新增/更正排除退款的接收与推荐两侧净额，原费用不被重新恢复。
- 本人当年、全局管理历史、管理字段隔离、附件原件读取和原键跨年恢复通过真实HTTP链路验证；HTTP使用合成登录会话，财务业务和附件使用实际PostgreSQL服务与本地文件存储。
- 共享客户端冻结提交内容和幂等键，角色变化时废弃旧读结果与旧命令；读接口不暴露内部路径或他人完整分配表。

## 边界

全部资料为本地合成资料，每个数据库测试创建独立schema并清理。没有调用银行卡转账、真实家长退款、真实凭证或生产环境。退款完整页面和微信真机验收分别跟踪，不能由本包后端通过代替。

0021是追加迁移，保留既有单据转换和不可变账本。升级前应保留数据库备份；退回旧代码不等于已冲回账务可以恢复，不能删除退款记录或反向账本来回退业务。
