# DEV-010 网页采买撤销验收

对应 PRODUCT F08/F11/F13：管理端撤销原内部采买划拨，个人查看撤销结果；教师周费用录入仍为首项。本包只修改网页、浏览器用例和读回脚本，不修改后端、client、迁移或主需求文档。统一执行日志由主任务整合。

## 环境与版本边界

为避开同时开发的普通报销0020迁移，本次API从已提交`1b344a0`导出到源码树外临时目录，内部workspace包链接指向该隔离副本，编译其API与19迁移；第三方依赖复用已安装目录。没有读取未提交后端服务。统一`npm run check`在该基线加本包网页源码上执行；主工作区未提交的普通报销集成不属于这个结果。已比对隔离副本与工作区的`self-purchase-panel.tsx`字节相同。

本地专用容器`alliance-weekly-ui-check`/PostgreSQL16，API3114，冻结网页构建预览5175。每轮启动全新独立合成schema，正常退出自动清理本次演示schema及外部临时原件。没有真实资料、银行调用、外部上传或上线。

## 已验证的业务行为

- 严格 GLOBAL 总部财务、管理员、开发者在COMPLETED管理详情办理，原因必填且勾选双侧影响；个人页面无办理入口，个人直接调用真实接口返回403。
- 明示原金额退回原业务账户、原申请人个人账户扣回同额，原单/原件保留；原始材料经真实上传，撤销后下载字节一致。
- 服务已撤销但响应丢失时冻结原请求、幂等键、原因和确认；详情/刷新锁住，跨页重试保留请求，退出受阻。重试成功但列表与详情均读取失败时，页面仍说明撤销已确认且不留旧表单。
- 另一管理员通过真实接口抢先撤销，旧网页提交真实409；清原因与勾选，独立重读列表/详情；详情读取故障不留下旧COMPLETED动作，刷新后显示另一办理人的撤销原因。
- 先真实提交提现把个人可用余额扣至0，再撤销12.34豆采买，个人余额成为-12.34豆。期间提现仍待转账、未被覆盖。随后56.78豆采买再撤销，个人仍为-12.34豆。
- 聚焦空schema的报销净额归零后页面隐藏该项；完整回归保留之前87.65豆未撤销采买，撤销前后报销收入回到原基线。390px截图与无水平溢出断言通过。

结果丢失及列表/详情读取失败使用明确HTTP故障注入；真实权限拒绝、第二办理人冲突、上传/下载、提现、采买、撤销、余额及账本均调用本地真实服务。没有把故障注入称作真实服务中断。
