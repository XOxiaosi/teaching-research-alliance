# DEV-010 小程序普通报销与周费用退款状态

对应 PRODUCT F06/F08/F13。小程序接入普通报销申请、总部财务人工审核和管理读取；教师周费用保持在个人财务面板之前。APPROVED 表示审核通过、等待后续划拨，本包没有报销执行入口。

## 范围与基线

前端只使用已提交 `980089c` 的归档副本进行最终验证，报销 API 来源 `690001e`，20 项迁移。内部 workspace 包链接指向副本，第三方依赖复用已安装目录。没有用另一个任务正在开发的 0021 退款实现代替稳定验收基线。

两端预先兼容 `refundStatus: ACTIVE | REFUNDED`，保留已退款周费用的历史登记金额，禁用金额、场地和保存；学生/教学期间仍可切换。收到 `WEEKLY_FEE_REFUNDED` 冲突后读取最新状态，不自动改写或重发。网页原登记累计明确包含已退款历史金额。本包对此采用合成 DTO 与错误响应注入；真实退款申请/批准/账务冲回留待 0021 稳定接口集成，不能将状态注入等同真实退款验收。

## 验证层次

- 默认自动化：真实 React 组件、真实 TeacherApiClient、Taro 控件与传输适配，覆盖原件版本、失败恢复、权限及父级入口。模拟响应只用于明确标注的边界场景。
- 可选本地 HTTP 集成：`apps/miniapp/test/integration/reimbursement-live.mjs` 挂载真实小程序报销组件，将 Taro.request 映射到本地合成 API。原件上传/下载、报销申请与审核使用真实 API；只对确认成功后的响应丢失进行故障注入，重试原幂等请求。比较提交与批准前后余额、收入，审核通过仍待划拨。
- 网页浏览器：真实网页控件，合成退款状态和 409 响应；不向稳定 API 写入退款或修改费用。
- 构建：统一 TypeScript/默认检查与 Taro 微信目标构建。
