# 数据库迁移

迁移文件按数字前缀顺序执行，目标数据库为 PostgreSQL。首个迁移只建立身份、账户、组织、职责和审计的基础表；费用、分配和不可变账本在 DEV-003–DEV-006 中追加，不在首个迁移里预先制造不完整的业务表。

本地开发只允许使用合成数据。可使用 Docker Desktop 启动隔离的 PostgreSQL 容器执行迁移和数据库门禁；不得连接真实业务数据库。`0004_ledger.sql`建立不可变事件/分录、余额投影和幂等载荷摘要字段；`0005_weekly_fee_history.sql`补充教学周开放状态、周费用版本快照和幂等请求表。账本事件与分录禁止更新和删除，余额投影由事务服务维护；周费用当前记录通过数据库触发器保留版本快照。每次新环境仍应从空库按数字顺序执行全部迁移，并记录迁移、约束和恢复验证证据。

当前本地验证使用 `postgres:16-alpine` 合成容器，映射到 `localhost:55432`，数据库名为 `teaching_research_alliance`。API 连接池通过 `DATABASE_URL` 注入连接字符串，账本适配器的真实发布与幂等重放、推荐接收和周费用版本/更正/幂等历史已在该库验证。容器名和启动方式只服务于本地开发，不作为生产部署配置。


`0006_settlement_snapshots.sql`新增持久化费率、结算运行与完整九项分配快照；计算运行和快照通过复合外键引用真实费用版本，历史使用递增序号排序。结算入口在同一个事务中保存周费、重算接收和介绍双方当月授课费用、按差额入账并更新余额；0豆及无差额保存运行与快照而不生成空账本事件。

集成检查为每个测试创建随机 schema，从空执行全部迁移，完成后只删除自身 schema；扩展在公共 schema 中串行初始化，测试禁止清空共享业务表。本轮亦使用新建的物理空数据库验证扩展初始化和并行迁移。日常本地 public schema 未自动升级到0006；新迁移不回填旧费用的结算运行，已有业务数据升级需另行核对费用、已有账本和基线快照，不能直接把全部旧费用再入账一次。
